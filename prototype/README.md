# CaseTwin — 触って確かめる試作

`index.html` をダブルクリックして Chrome で開く想定の、外部依存のない単一 HTML です。インストール、サーバー、アカウント、API キーは不要です。既定は日本語です。

添付の C3 画像に沿って、左に元の CSV、中央に失敗の指紋、右に架空の再現 CSV、下に操作の帯を置いています。共有前の画面も同じ配置を引き継ぎます。900px 以下では主要な列を縦に積み、560px 以下では補助のカードも縦に並べます。

この環境ではブラウザを起動していません。Chrome で実際に開けること、レイアウト、キーボード操作、画面読み上げは**未確認**です。画面の写しは作成していません。以下の手順で人が確認してください。

## 入っているファイル

- `index.html`：CSS、アイコン、見本データ、実処理、AI の固定回答をすべて内蔵。
- `verify.cjs`：HTML 内の実際のコードを取り出して検証する、Node 標準機能だけのテスト。
- `README.md`：この説明と確認手順。

## 5 操作で通す基本の流れ

1. 「見本の CSV を読み込む」を押します。`fictional-demo.csv` は架空の 64 データ行です。データ行 42 と 43 に `DEMO-FICTION-0042` が重複し、中央に `DUPLICATE_KEY`、列 `customer_id`、条件「同じ鍵が複数行にある」、検査の版 `r17` が出ます。
2. 「端末の AI の候補を見る」を押します。「見本の答え・実推論なし」と明記された固定回答が開き、「鍵の重複」が選ばれます。
3. 下の操作の帯の「架空の再現を作る」を押します。右に 3 行の `repro-synthetic.csv` ができます。データ行 2 と 3 の鍵は `SYN-FICTION-002` です。
4. 中央で元のデータ行 43 と架空のデータ行 3 がつながり、「同じ失敗を再現した」と表示されます。これは押すボタンではなく結果の表示です。「もう一度検査」は両方を同じコードで再検査します。
5. 「共有する物を確かめる」で共有前の画面へ進みます。報告の下書き、外へ出る物／出ない物を読み、確認のチェックを入れると「共有の束を書き出す」を押せます。4 ファイル分の JSON の**プレビューだけ**が開きます。送信、公開、クリップボード書き込み、ファイル保存、ダウンロードは行いません。

元のファイル名、元の値、元の行番号は画面内の私的な証拠として表示しますが、共有の束には入りません。報告は架空の再現の検査結果と静的な検査コードだけを引数として固定の見本から作っています。元の CSV や元の検査結果を報告関数へ渡していません。

### 追加の検査を触って確かめる

次の内容をそれぞれ UTF-8 の `.csv` として手元に保存し、ファイル入力から読み込めます。値はすべて架空です。「いいえ」で手動選択にすると分かりやすく試せます。

**必須列の不足**：`name` がありません。「必須列の不足」で再現すると `MISSING_COLUMN / name / required_column` が一致します。

```csv
customer_id
FICTIONAL-101
FICTIONAL-102
```

**セル内改行**：引用符内の改行です。「セル内の改行」で再現すると `EMBEDDED_NEWLINE / name / embedded_newline` が一致します。

```csv
customer_id,name
FICTIONAL-101,"Fictional
Person A"
FICTIONAL-102,Fictional Person B
```

**失敗のない CSV**：元が通過しても、失敗を再現したとは判定しません。共有前には進めません。

```csv
customer_id,name
FICTIONAL-101,Fictional Person A
FICTIONAL-102,Fictional Person B
```

**文字の符号**：UTF-8 として不正なバイトを含む架空のファイルで `INVALID_ENCODING` になります。符号名の自動判定や変換は行いません。手動で「文字の符号（UTF-8）」を選ぶと、実際に不正なバイトを含む再現を生成します。画面内の � は代替表示です。共有 JSON はこの再現だけ Base64 で保持し、復号すれば不正なバイトをそのまま再現できます。通常の UTF-8 文字として `�` を入力するだけでは、このエラーにはなりません。

必要なら Node 標準機能だけで次の架空のテストファイルを任意の作業フォルダに作れます。これは確認する人が任意で行う操作です。

```sh
node -e "require('node:fs').writeFileSync('fictional-invalid-utf8.csv', Buffer.concat([Buffer.from('customer_id,name\nFICTIONAL-101,Fictional Person '), Buffer.from([255,10])]))"
```

## 自動確認

このフォルダで実行します。

```sh
node verify.cjs
```

Node v26.13.0 で **30 項目が通過**しました。テストは隣の `index.html` のコードを直接読み、別に複製した実装は使いません。追加パッケージも外部通信も不要です。

確認内容は、64 行の見本と重複 1 組、決定的な 3 行生成、元のデータ値の不混入、既存の架空値との衝突回避、4 種の検査、CSV の引用符と改行、UTF-8 と BOM、指紋の各要素・版の不一致、通過同士を失敗一致としないこと、未承認や不一致での共有禁止、共有内容の許可リスト、書き出す検査コードの再実行です。

軽量なメモリ上の画面スタブでも、日本語初期表示、EN 切り替え、基本の操作順、手動選択、条件変更による無効化、プレビュー、入力のエスケープ、ファイルの読込失敗・上限・非同期読込の競合を確認しています。これは実ブラウザや DOM 実装による試験ではなく、描画や使いやすさの検証を代替しません。

## 処理とデータの境界

- CSV の読み込みは File API と `TextDecoder`、生成・検査・照合は同じ HTML 内の JavaScript です。データはページのメモリ内だけで扱います。Local Storage、IndexedDB、Cookie、サービスワーカーは使いません。閉じる・再読み込みでこのページの状態は失われます。
- 外部のスクリプト、CSS、画像、フォント、ライブラリはありません。アイコンはインライン SVG です。CSP でも `connect-src 'none'` とし、外部への接続を許していません。
- 端末 AI の候補は固定の見本です。読み込んだファイルに合わせた推論は行わず、最初は「鍵の重複」を勧めます。担当者は条件を変更できます。
- 雲の AI も固定の見本です。架空の再現の検査結果と検査コードから種類別のテンプレートを選びます。実際の AI、外部アプリ、本番のサービスは呼びません。
- 共有の束は `repro-synthetic.csv`、`importer-r17.cjs`、`validation.json`、`report-draft.txt` の許可リストで組み立てます。元の名前・値・行番号・生ログ・AI 候補は組み込みません。実際には何も外へ出ません。
- `validation.json` の元の検査結果は、成否、版、指紋、各検査の通過／失敗／未実行だけです。報告関数にはこの元の検査結果も渡しません。
- 架空の CSV の**データセルの値**が元のデータセルと完全一致しないことを生成時に確認します。`customer_id` と `name` は検査に必要な共通の列名なので維持します。「値の不混入」の対象にこのスキーマ名は含めません。元の値が短い一般文字列の場合、架空文字列の一部に偶然含まれることまで禁止するものではありません。

## 検査 r17 の仕様と範囲

1. UTF-8 として厳密に復号できるか確認します。BOM 付き UTF-8 は受け入れます。
2. CSV の引用符・列数・列名の重複を確認します。不正なら `CSV_FORMAT`。10,000 データ行超も明示的な失敗です。
3. `customer_id` と `name` の列の存在を確認します。名前は大文字小文字を区別し、空白の自動除去はしません。
4. 各データセルの CR / LF を検査します。引用符内の改行は CSV として解析した上で、この取り込みルールでは拒否します。
5. `customer_id` を文字列の完全一致で比較します。最初の重複で `DUPLICATE_KEY` を返します。

検査は最初の失敗で停止します。「未実行」は通過を意味しません。行番号は物理的なファイルの行ではなく、ヘッダーを除くデータレコードの番号です。

指紋は `kind`（種類）、`field`（列）、`condition`（条件）の 3 要素です。元と架空がどちらも失敗し、この 3 要素と検査の版が一致した時だけ再現成功です。行番号と値は比較しません。

生成器は `customer_id` / `name` のスキーマに対応し、重複、既知の列の改行、既知の必須列の不足、不正 UTF-8 を生成します。追加の任意列にある改行、壊れた CSV 構造、行数上限そのものの再現には対応しません。そうした場合の一致は保証せず、指紋が違えば共有前へ進めません。複数エラーの網羅的な診断、実データの意味や個人情報の推定、別の文字コードへの変換、実データベースへの書き込みは実装していません。

この `r17` は試作に内蔵した取り込み前の検査コードです。実サービスの取り込み処理・トランザクション・重複の許可方針を再現したという主張はしていません。

外部の資料を検索・取得していません。YouTube / X のページ・データ・字幕・埋め込み情報の取得、外部アプリへの書き込み・送信・公開も行っていません。
